## 0. 文档说明

### 0.1 目的与定位

本文档回答三个问题：

1. **做什么**：基于公司季报、年报、财报、相关新闻、K 线量价数据以及 PBR、市盈率等估值与财务指标，在日本上市股票全市场中识别可能被低估、被错杀且具备成长性的股票，评估其潜在上涨空间与收益风险特征，形成追求收益并兼顾风险的股票组合。
2. **依据什么做**：每一个筛选条件、参数、阈值都给出理由（市场制度、实证证据或工程约束），每一个数据都给出来源与口径，每一次结果都能回溯到当时的输入与参数。
3. **怎么落地**：把策略研究与程序化实现分开，先把策略讲清楚，再说明系统边界、模块、调度、记录与验证迭代的方式。

本文档不承诺任何收益。所有「上涨空间」「目标区间」均为基于明确假设的情景估计，并附带风险说明与失效条件。

### 0.2 阅读指南

- **研究篇（第 1–7 章）**：股票池、数据体系、筛选维度与参数、AI 辅助分析、输出规范、验证方法论。读者是策略研究者，也是实现工程师理解「为什么」的依据。
- **落地篇（第 8–20 章）**：功能边界、系统架构、数据接入、特征计算、筛选引擎、AI 服务、组合模块、调度与动态更新、记录与复现、验证流程、路线图、风险合规、待决问题。读者是实现工程师。
- **附录**：数据源速查表、指标口径公式表、参数与阈值 v0（另有 YAML 文件）、事件分类表、输出 Schema、术语对照、参考资料。

落地篇中凡引用研究篇的参数，均以「附录 C 参数 ID」为准，避免两处定义不一致。

### 0.3 核心原则

| 錯殺（本文定义） | 价格在短期内因事件或情绪大幅下跌，而基本面证据并未同等恶化的状态；是一个需要验证的假设，不是结论 |

# 第一部分 研究篇（策略研究）

## 1. 目标与问题定义

### 1.1 从投资目标到工程目标

| 投资目标（用户语言） | 工程化表述 | 本文档对应章节 |
|---|---|---|
| 在全市场中找出可能被低估的股票 | 对全部普通株计算估值指标，在同业与自身历史两个坐标系中定位，输出「低估候选」及其证据 | 4.2 |
| 找出被错杀的股票 | 识别短期大幅下跌事件，将下跌归因（业绩 / 事件 / 系统性 / 流动性 / 指数），并用基本面证据检验「未同等恶化」假设 | 4.3 |
| 具备成长性 | 用历史实绩、公司指引、进度率、修正历史、成长质量四类证据刻画成长 | 4.4 |
| 评估潜在上涨空间 | 用多种估值法给出 悲观 / 基准 / 乐观 三情景的价值区间，并说明每个情景的前提 | 6.3 |
| 评估收益风险特征 | 个股层面：波动率、流动性、失效条件；组合层面：集中度、因子暴露、情景压力 | 6.4 |
| 追求收益并兼顾风险的组合 | 在约束（单票、行业、流动性、市场区分、现金缓冲）下按策略篮子配置，定期再平衡，记录与验证 | 6.4、14 |

### 1.2 核心假设与证据等级

本工具的存在前提是：日本市场在某些局部存在可识别、可重复的定价偏差。每条假设都标注证据等级，并在第 7 章的验证流程中接受检验；证据不足的假设在参数上采用保守取值。

| 编号 | 假设 | 证据等级 | 依据概要 |
|---|---|---|---|
| H1 | 低 PBR / 低 PER 股票在日本长期存在超额收益，但在低 ROE 群体中大量是「价值陷阱」；PBR 相对自身历史的偏离比绝对水平更有信息 | 实证 | B/M 与现金流收益率是日本最显著的横截面变量（G2-01、G2-02）；但 Ken French 日本 HML 在 2010–2025 年仅约 2.8%/年、不显著，2023 年后回升（G2-04）；PBR 效应主要来自相对自身历史的「一时性」偏离（G2-05）；2023 年 PBR<1 组中 PER>15（ROE≤6.7%）的子组显著跑输（G2-06）；投资者偏好低 PBR 且高 ROE，效应不在 PBR=1 处跳跃（G2-07） |
| H2 | 業績予想是日本市场最重要的价格锚：公告日反应主要来自翌期预想意外；修正后约 1 个月存在同向漂移；公司层面存在稳定的预想偏差倾向（平均而言期初预想偏乐观、年内下修）；進捗率是实务常用但缺乏学术检验的上修领先信号 | 实证 + 经验 | 翌期预想意外主导公告反应（G2-14）；期初预想系统性乐观（G2-15）；未达后的强气预想约 65% 未达成（G2-16）；修正后 30 营业日 CAR 同向且低 PBR 股更强（G2-17）；PEAD 的 CAR[1,21] 极端十分位差约 2.2pp，且随时间减弱、在低外资/高个人持股公司持续（G2-18、G2-19）；進捗率无学术证据，按行业与自身历史标准化使用 |
| H3 | 短期大幅下跌后，若基本面证据未同等恶化，存在均值回归机会；但「下跌原因」决定回归概率，且无条件的急跌反弹中位数接近零 | 实证（短期反转）+ 假设（条件化） | 指数级 5 日 ≤ −10% 后 5 日反弹显著、可由流动性机制解释（G2-30）；个股跳空 ≥ −7% 后 5 日平均 +3.4%、胜率约 58%，而单日 ≥ −25% 的极端下跌次日平均为正但胜率仅 32%、中位数 0（G2-31，无成本回测）；2024-08-05 急落被官方归因于期货流动性枯竭而非基本面（G1-27）；条件化于基本面的版本需本工具自行验证 |
| H4 | 传统 12-1 个月动量在日本市场长期接近零，趋势维度应以较短期、行业相对与量价结构为主，权重较低；动量与价值组合仍有分散价值 | 实证 | 日本动量 Sharpe≈0.03 而价值 0.71，50/50 组合 0.65（G2-10）；Ken French 日本 WML 1990–2026 约 1.1%/年（t≈0.45）（G2-04）；52 周高点策略扣成本后多数市场不显著（G2-11） |
| H5 | 质量因子在日本是「去劣」而非「选优」：溢价为正但弱，主要价值在于降低价值陷阱与财务风险 | 实证 | AQR QMJ 日本约 2.5%/年（t≈1.5）（G2-12）；FF 日本 RMW/CMA 不显著（G2-02、G2-03）；应计异象在日本弱（G2-13）；因此质量作门槛与过滤，不作主排序 |
| H6 | 东证改革（「資本コスト対応」要请、TOPIX 成分改革、Growth 市场上市维持基准收紧）、回购与股东回报政策是可识别的催化剂 | 制度 + 实证 | 要请为非强制、披露率 Prime 94% / Standard 57%（G1-17）；回购公告 CAR(−5,+30) 平均 +4.7pp、PBR<1 约 6pp、规模依赖（G2-22、G2-23）；増配后次年増益概率更高（G2-24）；TOB 2025 年 135 件创纪录、平均溢价约 40%+（G2-28）；TOPIX 2026–2028 分阶段改革对小型股形成被动卖压（G1-18） |
| H7 | 新闻与披露对价格的影响可以分类、分级并有时效衰减；官方披露的可信度高于媒体，媒体高于社交平台；文本「乐观程度」不是正向信号 | 经验 + 实证 | 事件分类表（附录 D）；分割效应 30 日内归零（G2-25）；有報 MD&A 的 LLM 情绪与后续收益负相关（G2-35），收益标定词典优于零样本 LLM 情绪（G2-36），新闻方向预测准确率仅约 0.53（G2-37） |
| H8 | 小盘与低分析师覆盖股票的定价偏差更大，但 2013 年后无广义小盘溢价，流动性与信息质量更差 | 实证 + 工程约束 | 日本小盘股约 75% 零或一位分析师覆盖（G2-21）；规模溢价不稳定，仅市值 ≤100 億円 有残余超额（G2-20）；FF 日本 SMB 2013–2025 约 0.5%/年（G2-04）；PEAD 在低机构持股公司持续（G2-19）；需以流动性门槛与仓位上限对冲 |

### 1.3 非目标

- 不做日内或高频交易，不依赖实时行情；日线及以上粒度即可。
- 不做自动下单；输出的买入 / 卖出区间与触发条件供人工执行或后续独立的执行模块使用。
- 不预测宏观与指数点位；只识别市场环境（regime）并调整参数与现金缓冲。
- 不覆盖 ETF、ETN、REIT、インフラファンド、優先株、外国株（默认排除，可配置）。
- 不承诺收益率、胜率或回撤上限。

### 1.4 成功的定义：可度量的过程与结果指标

| 类别 | 指标 | 说明 |
|---|---|---|
| 数据过程 | 覆盖率、完整率、时效（披露到入库延迟）、跨源一致率 | 每日运行报告输出 |
| 筛选过程 | 候选数量稳定性、换手率、每条规则的触发频次 | 规则异常高频或零触发都是信号 |
| 证据质量 | AI 结论的引用命中率（抽样人工核验）、数值复核一致率 | 第 5.5 节 |
| 结果（历史） | 分层收益单调性、分维度贡献、命中率与校准度（情景区间是否包含后续价格） | 第 7 章；只报告统计，不做承诺 |
| 结果（前瞻） | 纸面组合跟踪：相对 TOPIX 与同风格基准的表现、最大回撤、换手与成本 | 按季度评估，驱动参数版本迭代 |

## 2. 股票池范围（Universe）

### 2.1 覆盖范围定义

| 维度 | 默认范围 | 可配置项 | 理由 |
|---|---|---|---|
| 交易所与市场区分 | 東京証券取引所 プライム / スタンダード / グロース 全部 | 名古屋・札幌・福岡 单独上市股（`universe.include_regional_exchanges`） | 东证三市场覆盖日本上市公司的绝大多数；地方单独上市股流动性极低，默认排除但保留数据 |
| 证券类型 | 普通株式（内国株） | 外国株（`universe.include_foreign_stocks`） | ETF/ETN/REIT/インフラファンド/優先株/出資証券 不属于「公司」分析对象 |
| TOKYO PRO Market | 排除 | — | 面向专业投资者的市场，披露与流动性不同 |
| 数据采集范围 | **全量**：上述全部市场的全部上市公司，加上回测期内已退市公司 | — | 本地全量数据库是硬性要求（第 0.3 节）；排除只发生在筛选阶段，不发生在采集阶段 |

### 2.2 分层：采集全量，筛选分层

| 层 | 定义 | 用途 |
|---|---|---|
| 全量库 | 全部上市股票（含 ETF 等非目标证券与已退市公司）的主数据、行情、披露 | 统计基准、回测、幸存者偏差控制 |
| 可投池 | 全量库中通过硬排除 X01–X07、X10 的普通株 | 评分对象 |
| 核心池 | 可投池中满足核心流动性门槛（第 4.6 节）与数据充足条件 | 篮子排序与组合候选 |
| 观察池 | 满足观察池流动性门槛但未达核心池 | 展示与跟踪；仓位上限减半 |

### 2.3 新股纳入规则

| 阶段 | 条件 | 处理 |
|---|---|---|
| 上市日起 | 出现在上市列表 | 进入全量库与新股观察池；记录 `listing_date`、公開価格、ロックアップ条款、VC 持股（来自有価証券届出書） |
| 观察期 | 上市 < 2 个季度 或 行情 < 60 个交易日 | 只计算行情、流动性与事件特征；估值用招股书财务数据并标记 |
| 初步评分 | ≥ 2 个季度且 ≥ 1 份決算短信且 ≥ 60 个交易日 | 进入可投池；成长与质量维度用缩减指标并标记低置信 |
| 完整评分 | ≥ 3 个会计年度实绩 | 全部维度正常计算 |

### 2.4 退市、代码变更与企业行动

- 退市（上場廃止）：保留全部历史；最后交易日之后无行情；回测时按最后可交易价处理。
- 代码变更与商号变更：`code_history` 表维护映射；内部 ID 不变。
- 市场区分变更、行业分类变更：按生效日记录，历史不回写。
- 分割 / 併合 / 配当：调整因子与企业行动日历；价格、股数、每股指标同步调整。
- 合并 / 分拆：被吸收方退市；分拆新设公司按新股处理。

**选型结论（v0）**

1. 主干：J-Quants Standard（¥3,300/月）。理由：10 年历史满足跨环境回测；日度无延迟；一个来源覆盖主数据、行情、估值、财务摘要、修正事件、决算日程、信用与空売り、EDINET 衍生的股东数据；条款允许个人使用与发布自己的分析结果。
2. 证据原文：TDnet（每日采集，免费）+ EDINET API（免费）。两者是「有迹可循」的根，所有 AI 结论最终引用这两类原文或 J-Quants 的结构化记录。
3. 财务明细：先用 EDINET 財務諸表本表 CSV（年度/半期）近似季度 EV/EBITDA 与 FCF；若季度精度不足，再升级 Premium 以获取 `/v2/fins/details`。
4. 历史披露回填：TDnet 官方站只保留约 1 个月，5 年历史通过 J-Quants TDnet 附加包一次性回填（订阅期间下载 td-bulk），之后用每日采集维持；注意附加包与主订阅同受「解約后删除数据」条款约束（第 19 章）。
5. 本地全量库与条款的关系：J-Quants 数据在订阅期内可本地保存与分析；若解約须删除。因此主干订阅应长期保持；同时把可永久保存的免费来源（JPX 文件、EDINET、TDnet 原文）作为长期档案，保证即使更换数据商，证据库与法定文件档案仍完整。
6. 新闻与第三方站点：日本主要媒体与聚合站（日経、株探、みんかぶ、Yahoo!ファイナンス、四季報オンライン、Buffett-Code、IR BANK）的规约几乎都禁止自动取得、蓄積或派生指标，因此 v0 的新闻维度以 L1 披露为主，L2/L3 只接入允许个人使用的标题级 RSS（Yahoo!ニュース 媒体 feed、PR TIMES），正文靠人工阅读；不抓取 日経 / Reuters / Bloomberg。
7. 全市场备援与交叉核对：KABU+（¥2,200/月，每小时 8 次访问上限，禁止再配信）提供全銘柄日频价格、PER/PBR/EPS/BPS 与年度财务，可作为 J-Quants 之外的第二口径与故障备援；Twelve Data Pro（$229/月）覆盖 JPX 全部约 3,982 只，仅在 J-Quants 不可用时考虑。
8. 共识预期与第三方预测（G9）：对个人没有合规的程序化来源（四季報オンライン禁止自动取得且不可导出；IFIS/QUICK 共识只在株予報 Pro、マネックス銘柄スカウター、SBI 画面或 ¥330/月的楽天 QUICKリサーチネット 中可见），因此 G9 只作为候选池的人工复核项，不进入自动评分。

### 3.5 可追溯证据链

- **证据 ID**：`EV-{source}-{docid}-{seq}`，`source ∈ {tdnet, edinet, jquants, jpx, news, metric}`；J-Quants 记录以 `(dataset, Code, DiscNo 或 Date)` 作 docid。
- **原文保存**：TDnet/EDINET 的 PDF、XBRL、CSV 原件落盘并记录 SHA-256；新闻保存标题、URL、抓取时间与正文快照（在条款允许范围内）。
- **片段定位**：证据片段带页码或字符位置（PDF）、XBRL 元素名（财务）或 API 记录键（结构化数据）；AI 输出只能引用已登记的证据 ID（第 5.3 节）。
- **血缘**：`features_daily` 每个指标记录输入记录 ID；`scores_daily` 记录规则 ID 与特征版本；`signals` 记录证据 ID 列表；复现流程（第 16.2 节）可从任一输出回溯到原始文件。
- **时间戳**：所有记录保存披露时间（JST）、获取时间（UTC）与生效日；证据的「当时可知性」由生效日保证。

### 3.6 数据质量与一致性校验

| 校验 | 规则 | 处理 |
|---|---|---|
| 估值口径一致 | 自算 PBR/予想 PER 与 J-Quants valuation 的差异 ≤ 5%（抽样全量每日） | 超限标记「口径待查」，排除当日评分 |
| 市场级一致 | 按 33 業種聚合的 PER/PBR 中位数与 JPX 月次统计方向一致 | 偏差大时检查股数或单位 |
| 修订处理 | 同一期间多条 `DiscNo` 时取 as_of 日前最新；保留修订链 | 记录 `revision_no` |

## 4. 筛选框架与维度定义

### 4.1 总体流程

```
S0 全市场主数据（上市列表、市场区分、行业、企业行动）
 └→ S1 硬过滤（可投资性：证券类型、监理/整理、流动性、数据充足性）
     └→ S2 特征计算（估值、成长、质量、趋势、事件；全部为时点数据）
         └→ S3 六维评分（同业百分位 → 0–100）
             └→ S4 策略篮子复合分（低估反转 / 成长 / 错杀修复）与排序
                 └→ S5 候选池（各篮子 Top N + 特殊情形池 + 观察池）
                     └→ S6 AI 深度分析（证据约束的阅读、横向比较、理由归纳、调整分）
                         └→ S7 复核门（规则复核 + 人工复核，具有否决权）
                             └→ S8 组合构建（约束优化 / 规则配置、买卖区间、触发条件）
                                 └→ S9 输出与记录（清单、个股卡片、组合报告、运行快照）
```

设计要点：

- **先便宜后昂贵**：S1–S4 只用结构化数据，可对全市场（约 4,000 只）每日运行；S6 的 AI 分析只对候选池（通常 100–200 只）运行，控制成本。
- **评分与硬过滤分离**：硬过滤只回答「能不能投」，评分回答「好不好」。任何评分都不能让硬过滤失效。
- **同业坐标系**：所有百分位默认在「東証 33 業種」内计算（跨市场区分合并，以保证样本量）；若行业内有效样本少于 20 只，回退到 17 業種；再不足则用全市场。同时保留全市场百分位供展示。
- **方向统一**：所有指标在评分前转换为「越高越好」的方向；缺失值不参与该指标评分，并记录该维度的「指标覆盖率」，覆盖率低于 60% 的维度分数标记为低置信。
- **金融业特殊处理**：銀行業、保険業、証券・商品先物取引業、その他金融業 四个行业的 EV 类、利息覆盖类、营运资本类指标无效，使用行业专用指标集（PBR、ROE、配当利回り、自己資本比率/规制资本），并在成长与质量维度上使用缩减版指标。

> **v0.2 修改**：S3、S4 的六维加权合成已停用，改为证据家族判定和篮子入池（4.11 节）。4.2–4.7 保留作研究记录和字段说明，指标是否使用、阈值和篮子要求以 `config/metric_registry.yaml` 与 `docs/指标与数据评估.md` 为准，两者不一致时以注册表为准。

### 4.2 维度一：低估（Value）

> **v0.2**：本节四大核心指标和价值陷阱规则已被注册表替换。现行判断用相对估值家族（PBR、预期盈利收益率、营业现金流收益率，三选二）和股东回报家族；EV/EBITDA、自身历史分位、国债利差、固定绝对线不再参与判断。见 4.11 节。

**目的**：回答「相对于同业、相对于自身历史、相对于无风险利率，现在的价格是否便宜」，并识别「便宜得有道理」的价值陷阱。

**指标定义（口径详见附录 B）**

| ID | 指标 | 计算口径 | 方向 | 理由 |
|---|---|---|---|---|
| V1 | PBR（実績） | 株価 ÷ 1株当たり純資産（最新四半期 自己資本 ÷ 自己株式控除後発行済株式数） | 低好 | 东证改革的核心指标；日本企业净资产口径稳定，可比性强 |
| V2 | 予想 PER | 株価 ÷ 会社予想 EPS（当期通期）；无公司指引时用直近 4 四半期 EPS 并标记 | 低好 | 日本市场惯例以会社予想为锚；指引修正是最重要的价格事件之一 |
| V3 | EV/EBITDA | （時価総額 + 有利子負債 − 現預金及び有価証券）÷（営業利益 + 減価償却費，直近 4 四半期） | 低好 | 中和资本结构差异，适合现金充裕的日本企业 |
| V4 | FCF 利回り | 3 年平均（営業CF − 投資CF 中的設備投資）÷ EV | 高好 | 规避会计利润与现金流背离 |
| V5 | 予想配当利回り | 会社予想年間配当 ÷ 株価 | 高好 | 日本市场股东回报政策明确，股息是重要的估值锚与下行支撑 |
| V6 | ネットキャッシュ比率 | （現預金 + 短期有価証券 − 有利子負債）÷ 時価総額 | 高好 | 日本上市公司普遍现金充裕；高净现金是回购与被收购（TOB/MBO）的常见背景 |
| V7 | 収益利回りスプレッド | 予想 E/P − 10 年国債利回り | 高好 | 把估值放在利率环境中比较；2024 年以来日本利率上行使此项变得重要 |
| V8 | 自身历史百分位 | PBR、予想 PER 在过去 5 年（不足则用可得期）中的百分位 | 低好 | 区分「行业整体便宜」与「公司自身被打折」 |

**条件与参数（v0 初值，附录 C 的 `value.*`）**

| 条件 | 规则 | 参数 | 理由 |
|---|---|---|---|
| 低估候选 | V1–V4 中至少 2 项处于行业 ≤30 百分位，且 V8 的 PBR 历史百分位 ≤ 40% | `value.core_metric_pct = 0.30`，`value.min_core_hits = 2`，`value.self_pct = 0.40` | 多指标共识降低单一指标噪音；历史百分位避免追「结构性低估行业」 |
| 强低估标记 | 满足任一：PBR < 1.0；予想 PER < 10；EV/EBITDA < 5；FCF 利回り > 8%；ネットキャッシュ比率 > 50% | `value.strong.*` | 绝对阈值取自日本市场长期分布的低位区间，作为展示用标签而非硬条件 |
| 价值陷阱降级 | 满足任一则「低估」维度分数乘以 0.6 并标记：3 年平均 ROE < 5%；PBR < 1 且 予想 PER > 15（隐含 ROE < 6.7%）；3 年売上 CAGR < 0；最近 3 年中 2 年営業CF 为负；減配；非金融业自己資本比率 < 20% | `value.trap.*` | 对应假设 H1：2023 年东证改革行情中，PBR<1 且 PER>15 的子组显著跑输（G2-06）；投资者奖励的是低 PBR 且高 ROE（G2-07） |
| 催化剂加分 | 满足任一加 5–10 分（上限 15）：已披露「資本コストや株価を意識した経営」对应方案并含量化目标；过去 12 个月公告自己株式取得；大量保有報告显示行动型股东持股 ≥ 5%；公告政策保有株式縮減目标或 DOE/累進配当政策 | `value.catalyst.*` | 对应假设 H6：低估需要催化剂才会收敛 |
| 金融业 | 只用 V1、V5、ROE、自己資本比率/规制资本比率；不使用 V3、V4、V6、V7 | `value.financial_sector_metrics` | EV 与现金口径对金融业无意义 |

**维度分数**：低估分 = 平均(V1、V2、V3、V4 的行业百分位倒数分) × 0.7 + 平均(V5、V6、V7、V8 分) × 0.3，再乘以陷阱系数，加催化剂分，截断到 0–100。

**实证依据摘要**：日本横截面收益中 B/M 与现金流收益率最显著（G2-01、G2-02），因此 V1 与 V4 为核心；EV/EBITDA 在日本缺乏学术证据，作为资本结构中性的补充指标；PBR 效应主要来自相对自身历史的偏离（G2-05），因此 V8 作为入池必要条件而非附属项；2010–2025 年价值溢价整体偏弱、2023 年后回升（G2-04），提示低估维度必须与催化剂和质量门槛组合使用。

**复核口径**：PBR 与 PER 必须与至少一个第二来源（J-Quants `/v2/equities/valuation` 与 JPX 月次 PER/PBR 统计）交叉核对，偏差超过 5% 时标记「口径待查」；季度净资产更新后 5 个交易日内须完成重算。

### 4.3 维度二：错杀（Oversold / Overreaction）

> **v0.2**：入池改由 1 个月行业调整后跌幅（`rev_1m`）决定；固定阈值触发只标事件日；价格反应比 R 和「预想未下修」F1 已移除；5 选 3 改为已知项全部通过（`rev_intact_test`）。见 4.11 节。

**目的**：找出「价格跌得多、证据跌得少」的股票。错杀是一个必须被验证的假设，本维度的产出是「错杀候选 + 下跌归因 + 基本面完好检验 + 企稳状态」，而不是「已确认错杀」。

**Step 1 触发：下跌事件识别（任一满足）**

| 规则 | 参数（v0） | 理由 |
|---|---|---|
| 从 60 个交易日高点回撤 ≥ 20%（時価総額 ≥ 3,000 億円 的大盘股 ≥ 15%），且回撤发生在 ≤ 20 个交易日内 | `oversold.trigger.drawdown_pct`, `oversold.trigger.drawdown_window_days` | 以「快速且深」区分错杀与长期下行 |
| 单日跌幅 ≥ 10%（大盘股 ≥ 8%），且成交量 ≥ 20 日平均的 3 倍 | `oversold.trigger.single_day_pct`, `oversold.trigger.volume_mult_vs_adv20` | 日本市场有値幅制限，单日 ≥ 10% 通常意味着重大事件 |
| 5 个交易日累计跌幅 ≥ 15% | `oversold.trigger.five_day_pct` | 捕捉连续跌停或连日抛售 |
| 排除：除息、分割、併合引起的价格跳变（用调整后价格并核对企业行动日历） | — | 避免假事件 |

**Step 2 归因：事件匹配与类型判定**

在事件日前 5 个交易日到后 1 个交易日的窗口内匹配 TDnet / EDINET / 新闻事件（附录 D 分类），并与行业指数、TOPIX 同期涨跌比较：

| 类型 | 定义 | 典型事件 | 默认处理 |
|---|---|---|---|
| T1 業績型 | 决算未达预期、下方修正、減配 | 決算短信、業績予想修正 | 进入 Step 3 检验 |
| T2 資本型 | 公募増資、売出、CB、MSワラント | 有価証券届出書、TDnet 公告 | MSワラント → 硬排除；其余进入 Step 3 并加「稀释」检验 |
| T3 事件型 | 不祥事、行政処分、訴訟、事故、主要顧客喪失 | TDnet、新闻 | 不適切会計 / 第三者委員会 → 硬排除；其余进入 Step 3 |
| T4 需給型 | 大株主売却、ロックアップ解除、指数除外、信用整理 | 大量保有報告、指数公告 | 进入 Step 3，优先级较高（基本面通常无关） |
| T5 系統型 | 行业指数或 TOPIX 同期跌幅 ≥ 个股跌幅的 2/3 | 宏观冲击 | 进入 Step 3，优先选择基本面优于同业者 |
| T6 不明型 | 无可识别事件 | — | 进入 Step 3，并由 AI 检索扩展窗口 |

**Step 3 基本面完好检验（五项通过 ≥ 3 项，且无硬失败项）**

| ID | 检验 | 参数 |
|---|---|---|
| F1 | 事件后公司通期営業利益予想未下修，或下修幅度 ≤ 10% | `oversold.intact_tests.f1_guidance_cut_max = 0.10` |
| F2 | 最新進捗率 ≥ 自身过去 3 年同季平均 − 5 个百分点 | `oversold.intact_tests.f2_progress_tolerance = 0.05` |
| F3 | 无红旗：継続企業注記、不適切会計、監査意見限定/不表明、決算発表延期 | — |
| F4 | 生存能力：自己資本比率 ≥ 30%，且（ネットキャッシュ > 0 或 ネット有利子負債/EBITDA ≤ 2） | `oversold.intact_tests.f4_*` |
| F5 | 配当予想维持或上调 | — |
| 硬失败 | MSワラント、債務超過、上場廃止決定、監理銘柄指定、継続企業注記 | — |

**Step 4 过度反应度量**

- 价格反应比 R = |事件窗口价格变动| ÷ max(|会社予想 EPS 变动|, 5%)。R ≥ 2 标记「反应过度候选」；T5 类型改用「实际跌幅 ÷ (β × 指数跌幅)」。
- 估值落点：事件后 PBR / 予想 PER 是否落入行业 ≤30 百分位；若是，错杀与低估形成共振（在篮子复合分中体现）。

**Step 5 企稳状态（决定「可进入买入区间」而非「可入池」）**

| 信号 | 规则 |
|---|---|
| 价格企稳 | 收盘价高于事件后最低收盘价 ≥ 3 个交易日 |
| 波动收敛 | 5 日 ATR 相对事件日起峰值下降 ≥ 30% |
| 量能回归 | 连续 3 日成交量 < 20 日平均 × 1.5 |
| 需給 | 信用買い残 相比事件前增加 < 50%（避免接盘套牢盘）；空売り残高未持续上升 |
| T1 业绩型的等待期 | 决算未达 / 下方修正后，企稳判定最早从公告后第 21 个交易日开始（PEAD 漂移窗口，G2-18） |
| 有效期 | 事件日起 60 个交易日内未企稳则移出候选（可被新事件重新触发） |

**维度分数**：错杀分 = 过度反应度量分（0–40）+ 基本面完好检验分（每项 10，最高 40）+ 企稳信号分（每项 5，最高 20）。T2/T3 类型即使通过检验，分数上限为 70（事件型风险的不可观测性更高）。

**实证依据摘要**：指数级急跌后的短期反弹有证据且与流动性机制相关（G2-30、G1-27）；个股层面，跳空 ≥ −7% 后的短期反弹平均为正但胜率仅略高于一半，极端单日下跌的反弹中位数为零（G2-31），说明无条件的「抄底」没有优势，必须叠加归因与基本面检验；指数除外股的负效应短暂且显著，可作为 T4 类候选来源（G2-29）；公募増資与 MS ワラント后的长期表现为负（G2-26、G2-27），因此 T2 类型设上限或硬排除。

**复核口径**：每个错杀候选必须附「事件证据 ID」「归因类型」「检验明细」；若 AI 判断的归因与规则引擎不一致，以保守者为准并标记待人工复核。

### 4.4 维度三：成长（Growth）

> **v0.2**：成长改由指引变化家族表达（翌期指引意外、期中修正）。历史 CAGR、増収増益年数、进捗率只展示或不用，B2 改名为「指引改善」。见 4.11 节。

**目的**：区分「有证据的持续成长」与「一次性或会计驱动的增长」，并利用日本市场特有的指引制度（業績予想、進捗率、修正）捕捉成长预期差。

**指标定义**

| ID | 指标 | 口径 | 方向 | 理由 |
|---|---|---|---|---|
| G1 | 売上高 CAGR（3 年） | 最新通期 vs 3 期前通期；决算期变更时按月数折算 | 高好 | 3 年平滑单年波动；5 年作为可选补充 |
| G2 | 営業利益 CAGR（3 年） | 同上；基期为负或接近零时标记不可用 | 高好 | 日本市场对営業利益的关注高于净利润（净利润受特別損益影响大） |
| G3 | 予想営業利益成長率 | 会社予想（当期通期）÷ 前期実績 − 1 | 高好 | 指引是最被关注的锚 |
| G4 | 増収増益連続年数 | 売上与営業利益同时同比增长的连续年数 | 高好 | 稳定性证据 |
| G5 | 営業利益率水平与趋势 | 最新通期営業利益率；3 年变化（百分点） | 高好 | 质量化的成长：规模扩大伴随盈利能力改善 |
| G6 | 進捗率偏差 | 累计季度営業利益 ÷ 通期予想 − 自身过去 3 年同季平均進捗率 | 高好 | 季节性调整后的进度偏差是上修的领先信号（假设 H2） |
| G7 | 修正履歴 | 过去 3 年上方修正次数；実績 ÷ 期初予想 的 3 年平均 | 高好 | 识别公司自身的预想偏差倾向：日本公司平均而言期初预想偏乐观、年内下修（G2-15），因此「习惯性保守」是少数且有价值的特征 |
| G8 | 成长质量 | 3 年平均 営業CF ÷ 営業利益；（売上債権 + 棚卸資産）增速 − 売上增速 | 高好 / 低好 | 排除靠压货、放宽信用实现的增长 |
| G9 | 第三方预测差（人工） | 四季報独自予想 或 IFIS/QUICK コンセンサス − 会社予想 | 高好 | v0 没有面向个人的合规程序化来源（四季報オンライン禁止自动取得、共识只在网页/券商工具可见），只作为候选池人工复核项，不进入自动评分 |

**条件与参数（v0，附录 C `growth.*`）**

| 条件 | 规则 | 理由 |
|---|---|---|
| 成长候选（实绩路径） | G1 ≥ 8% 且 G2 ≥ 10% 且 G3 ≥ 10% 且 G8 的 OCF/営業利益 ≥ 0.7 | 日本名义 GDP 增速低，8%/10% 已明显高于市场中位；现金流约束防止会计增长 |
| 成长候选（预期差路径） | G6 ≥ +5 个百分点 且（G7 上方修正 ≥ 2 次/3 年 或 実績/期初予想 ≥ 1.05） | 捕捉「指引保守 + 进度领先」的上修候选 |
| 成长降级 | G8 中（売上債権 + 棚卸資産）增速超过売上增速 10 个百分点以上；或 G5 营业利润率连续 2 年下降；或「未达后强气予想」：上期実績未达预想且翌期予想増益率高于行业中位 2 倍以上（G3 × 0.7） | 增长质量恶化；未达后发布的强气预想约 65% 未达成（G2-16） |
| 高成长亏损桶（默认关闭） | Growth 市场公司：G1 ≥ 30%，売上総利益率 ≥ 50%，现金可支撑 ≥ 24 个月经营性现金流出 | 单独篮子、单独风控，不与核心策略混合 |

**進捗率的实现细节**：

- 分母为「当期最新通期予想」；若公司未披露通期予想（东证允许在特定条件下不披露），G6 缺失并标记。
- 同季平均用公司自身历史（至少 2 年，否则回退到 33 業種同季中位数）。
- 第 2 四半期（中間）后的偏差权重最高（已过半年，指引修正最密集）；第 1 四半期权重最低。
- 進捗率没有学术检验支持（仅实务经验），因此只作为「预期差路径」的条件之一，并在第 7 章验证中单独统计其命中率；若样本外无效则降级为展示字段。
- 日本市场对業績公告的反应主要来自翌期予想的意外（G2-14），因此 G3 与修正事件（E01/E02）是成长维度中证据最强的部分。

**维度分数**：成长分 = 实绩成长（G1、G2、G4、G5 行业百分位均值）× 0.4 + 预期成长（G3、G6、G7 行业百分位均值）× 0.4 + 成长质量（G8）× 0.2，再按降级规则调整。

### 4.5 维度四：质量（Quality）

> **v0.2**：现行判断用经营质量家族（7 项简化 F-Score、营业利润/总资产）和风险门槛。F-Score 未知时整个家族记未知。见 4.11 节。

**目的**：衡量盈利能力、财务健康、会计可信度、资本配置与治理，并作为价值陷阱与错杀误判的主要防线。

| ID | 指标 | 口径 | v0 参考阈值 | 理由 |
|---|---|---|---|---|
| Q1 | ROE（3 年平均） | 親会社株主に帰属する当期純利益 ÷ 期首期末平均自己資本 | ≥ 8% 良；< 5% 差 | 8% 是「伊藤レポート」与东证改革中被广泛引用的资本成本参考线 |
| Q2 | ROIC | NOPAT ÷（有利子負債 + 自己資本） | ≥ 7% 良 | 不受杠杆影响的盈利能力 |
| Q3 | 営業利益率稳定性 | 5 年営業利益率标准差 | ≤ 3 个百分点 良 | 周期性与经营稳定性 |
| Q4 | 自己資本比率 | 自己資本 ÷ 総資産 | 非金融 ≥ 30% 良，≥ 40% 优；< 20% 差 | 财务安全边际 |
| Q5 | ネット有利子負債/EBITDA | （有利子負債 − 現預金）÷ EBITDA | ≤ 2 良；> 4 差 | 偿债能力 |
| Q6 | インタレスト・カバレッジ | 営業利益 ÷ 支払利息 | ≥ 5 良 | 利率上行环境下重要性上升 |
| Q7 | アクルーアル比率 | （当期純利益 − 営業CF）÷ 総資産（3 年平均） | ≤ 10% 良；> 20% 差 | 会计利润与现金流背离是盈余质量红旗 |
| Q8 | 営業CF 为正年数 | 最近 3 年 | 3/3 良 | 现金生成能力 |
| Q9 | 配当记录与政策 | 5 年内是否減配；是否有明示政策（DOE、累進配当、配当性向目标） | 无減配且有政策 良 | 股东回报承诺的可信度 |
| Q10 | 资本配置行为 | 过去 12 个月自己株式取得；政策保有株式縮減；「資本コスト対応」开示质量 | 有量化目标 良 | 低估收敛的催化剂（假设 H6） |
| Q11 | 治理与会计红旗 | 不適切会計、第三者委員会、監査意見、監査法人頻繁交代、決算発表延期、上場維持基準未達、MSワラント、稀释 ≥ 10%、債務超過 | 任一 → 红旗 | 以制度性事件为依据，可追溯 |
| Q12 | 股东结构 | 親子上場（上市子公司）、政策保有比率、浮動株比率 | 展示用 | 親子上場既是少数股东风险，也是 TOB 潜在催化剂；不作硬条件 |

**条件与参数（附录 C `quality.*`）**：

- 质量门槛（进入核心篮子的必要条件）：Q4 ≥ 30%（非金融）、Q8 ≥ 2/3、无 Q11 红旗。
- 设计立场：日本的质量溢价为正但弱（AQR QMJ 约 2.5%/年，t≈1.5；FF 日本 RMW 不显著；应计异象弱，G2-12、G2-02、G2-13），因此质量用于「去劣」（门槛、红旗、陷阱过滤）而非「选优」排序；质量分在篮子权重中主要起稳定作用。
- 质量分 = 盈利能力（Q1–Q3）× 0.4 + 财务健康（Q4–Q6）× 0.3 + 盈余质量（Q7–Q8）× 0.2 + 回报与治理（Q9–Q10）× 0.1；红旗直接把质量分置为 0 并触发排除规则。
- 金融业使用：ROE、自己資本比率（或规制资本比率）、配当记录、红旗。

### 4.6 维度五：趋势与流动性（Trend & Liquidity）

> **v0.2**：趋势类指标只展示，不进入判断和排序；流动性门槛不变，篮子只取流动性核心池。

**定位**：在日本市场，12-1 个月传统动量的证据弱于其他市场（假设 H4），因此趋势维度主要用于 **择时与风险控制**，权重较低；流动性是 **硬约束**。

| ID | 指标 | 口径 | 用途 |
|---|---|---|---|
| T1 | 均线结构 | 收盘价相对 25/75/200 日均线位置；均线排列 | 阶段判定 |
| T2 | 均线斜率 | 25 日与 75 日均线 20 日变化率 | 阶段判定 |
| T3 | 相对强弱 | 1/3/6 个月相对 TOPIX 与相对 33 業種指数的超额收益 | 行业相对动量（证据强于绝对动量） |
| T4 | 52 周高点距离 | 收盘价 ÷ 52 周最高收盘价 | 错杀与突破识别 |
| T5 | 量能趋势 | 20 日平均売買代金 ÷ 120 日平均 | 关注度变化 |
| T6 | 波动率 | ATR(14)/株価；60 日实现波动率 | 止损与仓位 |
| T7 | β | 250 日相对 TOPIX 回归 | 组合风险 |
| T8 | 信用需給 | 信用倍率；信用買い残 ÷ 20 日平均出来高（消化天数） | 上方套牢盘压力 |
| T9 | 空売り残高 | JPX 空売り残高報告（≥0.5% 持仓）合计 | 空头拥挤度 |
| T10 | 阶段分类 | 基底 / 上升 / 顶部 / 下降（基于 T1–T4 规则） | 篮子内的入场时机 |

**流动性硬过滤（附录 C `liquidity.*`，与资金规模挂钩）**

- 单只持仓上限 = 20 日平均売買代金 × 参与率 5% × 可退出天数 5 日。例如：目标单票仓位 100 万円 → 要求 20 日平均売買代金 ≥ 400 万円；目标 1,000 万円 → ≥ 4,000 万円。
- 核心池：20 日平均売買代金 ≥ 5,000 万円 且 時価総額 ≥ 50 億円；观察池：≥ 1,000 万円 且 ≥ 20 億円。低于观察池门槛只保留在全市场统计中。
- 浮動株比率 < 15% 的公司标记「流通盘过小」。

**趋势分**：趋势分 = 阶段分（0–40）+ 相对强弱（T3，0–30）+ 量能与需給（T5、T8、T9，0–30）。趋势分在「错杀修复」篮子中只用于企稳判断，不参与排序。

**实证依据摘要**：Ken French 日本 WML 1990–2026 年约 1.1%/年、不显著（G2-04）；Asness (2011) 指出日本动量单独无效但与价值 50/50 组合的 Sharpe 显著高于单独价值（G2-10），因此趋势维度的作用是组合层面的分散与择时，而非选股 alpha；1 个月短期反转在日本存在（G2-30），与错杀维度衔接。TOPIX 2026–2028 年分阶段改革会对移行措置銘柄形成持续的被动卖压（G1-18），需在 T4 需給型归因与指数事件表中记录。

### 4.7 维度六：新闻与披露影响（News & Disclosure）

> **v0.2**：手工事件总分不参与判断，只展示。有证据的事件类别进入对应家族。公告数据不覆盖基准日时显示未知，不算没有坏消息。

**目的**：把非结构化信息转为可追溯、可衰减、可验证的事件分数，并为 AI 深度分析提供证据片段。

**来源分级（可信度）**

| 级别 | 来源 | 用途 |
|---|---|---|
| L1 官方披露 | TDnet 适时披露、EDINET 法定文件、JPX 公告 | 事件判定的唯一依据；可直接触发规则 |
| L2 主流媒体 | 日本経済新聞、Reuters、Bloomberg、時事/共同 | 补充背景与解释；可触发「待核实」标记 |
| L3 聚合与专业站 | 株探、みんかぶ、Yahoo!ファイナンス ニュース 等 | 发现线索；需回溯到 L1/L2 |
| L4 社交与论坛 | X、掲示板、note | 仅作「关注度」指标，不作证据 |

**事件的制度完整性**：業績予想修正受上場規程强制披露（売上高 ±10%、営業利益・経常利益・純利益 ±30%），配当予想修正无軽微基準，因此 E01–E04 类事件在 TDnet 中是完整、可穷举的；低于阈值的业绩变化只在下一份短信中出现，進捗率（G6）正是对这部分「阈值以下信息」的代理（第 3.7 节）。

**事件分类与分值（摘要，完整表见附录 D）**

| 事件类别 | 方向 | 强度（−3…+3） | 半衰期（交易日） |
|---|---|---|---|
| 上方修正 / 下方修正 | + / − | ±3 | 20 |
| 増配 / 減配 / 配当予想修正 | + / − | ±2 | 20 |
| 自己株式取得（含取得枠规模 ≥ 时价总额 2%） | + | +2（≥ 5% 为 +3） | 60 |
| 公募増資・売出・CB | − | −2 | 60 |
| MSワラント | − | −3（硬排除） | 永久直至消化 |
| TOB / MBO / 完全子会社化 | + | +3（进入特殊情形池） | 事件结束 |
| 資本業務提携・大型受注 | + | +1 | 20 |
| 不祥事・行政処分・不適切会計 | − | −3（不適切会計硬排除） | 120 |
| 監理・整理銘柄指定、上場廃止 | − | 硬排除 | — |
| 株式分割 | + | +1（流动性改善） | 20 |
| 「資本コスト対応」開示（含量化目标） | + | +1 | 120 |
| 大量保有報告（行动型股东 ≥ 5%） | + | +2 | 120 |
| 決算発表延期 / 監査法人交代 | − | −2 / −1 | 60 |

**新闻分计算**：新闻分 = Σ（强度 × 来源权重 × 0.5^(Δt / 半衰期)），来源权重 L1 = 1.0、L2 = 0.6、L3 = 0.3，截断到 −100…+100 后线性映射到 0–100。

**冲突与去重规则**：同一事件多源报道只计一次（以 L1 为准）；媒体解读与官方披露方向相反时以官方为准并标记「解读分歧」；无法回溯到 L1/L2 的 L3 信息不计分。

**AI 在本维度的任务**：事件分类、数值抽取（修正幅度、回购规模、稀释比例）、与结构化数据的交叉校验、生成带引用的一句话摘要、识别「旧闻重提」。详见第 5 章。

**不做的事**：不把文本的「乐观程度」当作正向信号。对有価証券報告書 MD&A 的 LLM 情绪与后续收益呈显著负相关（G2-35），零样本 LLM 情绪弱于收益标定词典（G2-36），新闻方向预测准确率仅约 0.53（G2-37）。因此文本情绪只用于「过度乐观警示」与事件抽取，不进入正向评分。

| B0 特殊情形 | TOB/MBO、活动股东、分拆等 | 不评分，按事件逻辑单独呈现 | | | | | | 事件触发 |

- 每个篮子输出 Top N（v0：N = 40），同一股票可同时进入多个篮子（共振标记）。
- 篮子权重是 v0 先验，在第 7 章的验证中按「分维度贡献」校准；权重变更必须生成新的参数版本。

### 4.10 复核口径

复核的目的是让每一个进入组合的股票都能回答「凭什么」。复核分三层，每一层都有否决权，否决必须写明原因码与证据。

| 层 | 执行者 | 内容 | 否决条件示例 |
|---|---|---|---|
| R1 规则复核（自动） | 筛选引擎 | 数据新鲜度（最新決算短信距今 ≤ 135 天；行情 ≤ 1 个交易日）；口径一致（会计准则、連結/単体、決算期变更）；跨源差异 ≤ 5%；企业行动已调整 | 任一不满足 → 标记「数据待查」，不得进入组合 |
| R2 AI 复核（半自动） | AI 分析服务 | 对规则引擎的每个关键判断（低估、错杀归因、成长证据、红旗）给出「支持 / 反对 / 不确定」及证据 ID；生成反方论点 | AI 引用的证据无法在证据库中命中 → 该结论无效 |
| R3 人工复核 | 使用者 | 阅读个股卡片与证据；确认买卖区间与触发条件；记录人工判断 | 任何未被证据支持的乐观假设 |

复核产出写入 `review_log`，字段包括：候选 ID、运行 ID、复核层、结论、原因码、证据 ID 列表、复核人/模型版本、时间戳。

### 4.11 多证据原则与筛选理由

**来源**：使用者要求「股票的筛选不能光靠 PBR 之类的单一参数，而且要明确筛选理由」，并说明 PBR 只是举例，指标要认真评估。因此没有任何指标在代码、规则、测试和文字里有特殊地位。指标集来自 `config/metric_registry.yaml`，选择依据见 `docs/指标与数据评估.md`。下面是硬规则，不是权重。这些规则没有用收益回测过，全部阈值是先验。

**硬规则**

1. 每只股票每天每个证据家族判定为 hit、miss、fail、unknown 或 inactive。数据缺失是 unknown，绝不算通过，也绝不算不通过。行业、市场或公司不适用时是 inactive，不计入覆盖率。
2. 入池需要至少 `evidence.min_families`（默认 3）个家族 hit，同时满足注册表 `buckets` 的要求。一个家族内多个指标只算一份证据。
3. 篮子只取流动性核心池。硬排除的股票不进任何篮子。
4. 一个家族在某市场能判断的比例低于 60%（`family_policy.coverage_floor`）时不能作必要条件：它是篮子的 anchor 就暂停这个篮子，是附加条件就放行并标低置信。回填或接入新数据后自动生效。
5. 同一篮子内先按命中家族数，再按 anchor 家族的同业分位排序。不做跨家族加权。触发降级门槛的减一个家族（`evidence.downgrade_penalty`）。

**证据家族**（阈值在注册表 `families`，下表只是摘录）

| 家族 | 回答的问题 | 指标 | 怎样算 hit | fail |
|---|---|---|---|---|
| 相对估值 | 和同业比便宜吗 | PBR、预期盈利收益率、营业现金流收益率 | 已知至少 2 项，2 项进入同业最好 30%；一次性利润标记时预期盈利收益率不算 | 无 |
| 股东回报 | 实际还给股东多少现金 | 预想股息率 | 进入同业最好 30%，且分红有利润覆盖 | 无 |
| 经营质量 | 生意赚不赚钱、在变好吗 | 7 项简化 F-Score、营业利润/总资产 | F-Score 至少 6 分，或盈利能力进入同业最好 30%；F-Score 未知时整个家族未知 | F-Score 不超过 2 |
| 指引变化 | 公司对未来的说法刚变好了吗 | 翌期指引意外、期中业绩预想修正 | 指引意外减同业中位后进入同口径最好 30%（60 个交易日内）；或上调幅度进入窗口内上调事件最好 30% 且不低于市值的 0.5%（30 个交易日内） | 30 个交易日内下调且主业也下调，或撤回预测 |
| 资本行动 | 最近有没有用真金白银回报股东 | 配当预想上调 | 30 个交易日内上调过 | 无 |
| 价格错位 | 是否比同行跌得特别多 | 1 个月行业调整后跌幅 | 进入流动性核心池跌幅最大的 10% | 无 |

**篮子要求**（注册表 `buckets`）

| 篮子 | 必须 hit | 另需 | 不得出现 |
|---|---|---|---|
| B1 低估反转 | 相对估值 | 经营质量、股东回报、指引变化、资本行动至少一个；周期公司不接受只靠股息 | 经营质量或指引变化 fail；不在 Growth 启用；保险业除外 |
| B2 指引改善 | 指引变化 | 经营质量（覆盖率够时）；预期盈利收益率不在同业最差 30% | 金融业除外 |
| B3 错杀修复 | 价格错位 | 基本面完好检验；决算附近的大跌先等待 21 个交易日（翌期指引差时最长 60 日） | 指引变化 fail；保险、证券除外 |

注册表的篮子要求本身允许两个家族（B1）甚至一个家族（B2、B3 在经营质量覆盖不足时）入池，`min_families` 是在它之上加的一道：否则 B2、B3 可能只靠一个指标入选，违反硬规则。把 `evidence.min_families` 改成 2 可以看到更接近注册表规模检查的结果。

**单指标依赖检验（留一法）**

对每个候选，把注册表里每个 score 指标轮流当作不存在（所有指标一视同仁），重算家族状态和排序键，看排名掉到哪里。去掉任何一个指标后排名超过 `bucket.top_n × evidence.loo_rank_mult`（默认 40×2=80）的，从清单移除并写明原因。结果按股票记录：`loo_worst_rank_*`、`loo_worst_metric_*`、`loo_removed_*`，每个指标对应的排名在 `bucket_check` 里。入池人数不超过 80 时这条按定义不会移除任何人，此时看 `bucket_check` 的 `critical`：列出去掉后家族数就不够门槛的指标，会写进反面理由。

**证据集中标记**：排序键不是加权平均，没有传统意义上的「贡献占比」，所以按每个命中家族超过门槛的幅度计算占比（分位规则：(门槛−分位)/门槛；是非类规则如 F-Score、配当上调记 0.5，这个数是约定，不是度量）。某个家族占比超过 `evidence.max_dimension_share`（默认 0.5）时标记 `concentration_flag`，只提示，不移除。

**理由格式**（`screener/reasons.py`，确定性生成，不用 AI）

稳定接口：`build_reasons(row, params) -> dict`、`exclusion_reason(row, params) -> str`，只读 `scores_daily` 的存储列。

| 字段 | 内容 |
|---|---|
| `reasons` | 候选命中的每个指标一条：`family`, `rule_id`, `metric`, `label_zh`, `plain_zh`, `value`, `threshold`, `comparison`, `peer_pct`, `self_pct`, `peer_group`, `as_of`, `source`, `text_zh`。`peer_pct` 越小越好。`text_zh` 含注册表的白话和实际数字，数字由存储值格式化，有测试保证一致 |
| `counter_reasons` | 同样结构：价值陷阱类门槛、被门槛拦下的指标、软标记、fail 或没命中的家族、数据偏旧、证据集中、少一项就不够 |
| `unknowns` | 判断不了的家族和需要什么数据；未检查的门槛必须列出，不能显示为通过；公告不覆盖、Free 数据延迟也写在这里 |
| `selection_summary_zh` | 一两句话：哪个篮子、排第几、几个家族命中、最强的两个家族和数字 |
| `exclusion_reason_zh` | 未入选的股票：每个 X 码和每条没满足的篮子要求各一句中文 |
| `family_status` | 每个家族的状态和每个指标的值、分位、同业、来源 |

**尚未覆盖的部分**：注册表 `gates.unchecked_on_current_data` 列出的僵尸企业、偿债能力、周期顶点、净资产质量和下跌原因分类现阶段是「未检查」。偿债能力在 `edinet_key_items` 有数据的公司上已能算出，但注册表状态是 display，只进反面理由，不影响入池；通过指标评估工具检验并改注册表后才生效。

## 5. AI 辅助分析层

### 5.1 定位与边界

AI（大语言模型）在本工具中的角色是 **受证据约束的分析员**，不是数据源，也不是最终决策者：

- AI 不产生任何数值型事实；所有数字来自结构化数据库，AI 只能引用并解释。
- AI 的每个结论必须附证据 ID（文档 ID + 位置），引用不命中则结论作废。
- AI 可以对规则分数提出调整建议，调整幅度有上限（±10 分），且不能越过硬过滤与复核门。
- AI 的输出是结构化 JSON（Schema 见附录 E），便于校验、存储与复现。

### 5.2 任务类型

| 任务 | 输入 | 输出 | 触发时机 |
|---|---|---|---|
| A1 決算短信解读 | 短信 PDF/XBRL 摘要 + 上期对比 + 公司预想 | 要点、超预期/不及预期判断、指引变化、管理层措辞变化（含引用） | 每次新短信入库 |
| A2 業績修正解读 | 修正公告 + 历史修正记录 | 修正性质（一次性/结构性）、对估值的影响方向、与進捗率的一致性 | 修正公告入库 |
| A3 事件分类与抽取 | TDnet/EDINET 标题与正文、新闻 | 附录 D 类别、方向、强度、关键数值（回购规模、稀释比例）、证据片段 | 每条事件入库 |
| A4 下跌归因 | 错杀触发记录 + 窗口内事件 + 行业走势 | 归因类型 T1–T6、置信度、证据、与规则引擎判定的差异说明 | 错杀触发 |
| A5 同业横向比较 | 同篮子同行业候选的指标表 + 各自证据摘要 | 相对优劣排序、每家的差异化理由、共同风险 | 候选池形成后 |
| A6 论点与反论点 | 个股全部证据 | 多头论点（≤ 5 条）、空头论点（≤ 5 条）、关键不确定性、需要跟踪的验证点 | 候选池形成后 |
| A7 理由归纳与卡片生成 | A1–A6 输出 + 规则分 | 一句话论点、三条核心理由、风险清单、失效条件；全部带引用 | 输出前 |
| A8 评分调整建议 | 规则分 + A6 | 各维度 ±10 分以内的调整与理由 | 输出前 |
| A9 复核辅助 | 规则引擎判断 | 「支持 / 反对 / 不确定」+ 证据 | 复核门 R2 |

### 5.3 提示设计与证据约束

- **证据包**：每次调用只提供该股票的证据包（结构化指标表、事件列表、文档片段），每个片段带 `evidence_id`。系统提示要求「只能引用证据包内的 ID；无证据的推断必须标记为 `inference` 并说明依据」。
- **数值复核**：AI 输出中的每个数字都会被程序与结构化数据比对，误差超过 1% 的数字标记为 `number_mismatch`，该结论降为「待复核」。
- **引用校验**：程序检查输出中的 `evidence_id` 是否存在、片段是否与结论主题相关（用关键词与数值共现规则）。
- **稳定性**：对关键判断（归因类型、方向）采用多次采样取多数（v0：3 次），分歧时标记低置信。
- **语言**：原文为日文，输出为中文，但关键术语保留日文原文并附证据片段原文，避免翻译歧义。
- **文档输入**：決算短信与有報以 PDF 或抽取文本输入；使用 API 的文档引用功能（document 内容块 + citations），由模型返回带页码/字符位置的引用，程序再映射为 `evidence_id`。

### 5.4 模型与成本策略

以 Claude API 为例（实现阶段以官方文档为准；下列价格为 2026 年 10 月缓存的参考值）：

| 任务 | 建议模型 | 理由 |
|---|---|---|
| A3 事件分类、A1 批量短信解读（全市场） | `claude-sonnet-5-5`（$2/$10 每百万 token）或 `claude-haiku-5-5`（$0.10/$0.50） | 高频、模式化、可用结构化输出严格约束 |
| A4–A8 候选池深度分析 | `claude-opus-5-5`（$4/$20 每百万 token，默认） | 需要跨文档推理与反方论点质量 |
| 复核辅助 A9 | `claude-opus-5-5` | 否决权相关，质量优先 |

成本控制手段：

1. **Message Batches**：非实时任务（全市场短信解读、事件分类）走批处理端点，成本减半，24 小时内完成即可。
2. **Prompt Caching**：系统提示、术语表、评分规则放在稳定前缀；证据包放在后部，命中缓存后输入成本显著下降。
3. **结构化输出**：用 `output_config.format`（JSON Schema）约束输出，减少解析失败与重试。
4. **分层调用**：全市场只跑 A3；候选池跑 A1/A2/A4；Top N 跑 A5–A8。
5. **缓存结果**：同一文档 + 同一提示版本 + 同一模型版本的输出永久缓存，运行时直接复用（可复现的前提）。

成本量级估算（v0，供预算，不是承诺）：全市场每季约 4,000 份短信 × 平均 15k token 输入 ≈ 6,000 万 token；按 Sonnet 批处理价约 60 美元/季；候选池深度分析每月 200 只 × 约 60k token ≈ 1,200 万 token，按 Opus 价约 50–100 美元/月。

### 5.5 评分、排序与可解释性

- 最终分 = 规则复合分（篮子权重）+ AI 调整分（上限 ±10）。AI 调整必须给出「调整理由 + 证据 ID」，否则忽略。
- 排序在篮子内进行；跨篮子不比较分数，只按组合配置比例分配名额。
- 每个候选的可解释输出包括：各维度分、触发的规则 ID 列表、排除/降级码、AI 调整与理由、证据 ID 列表。任何人都可以从这些字段回溯到原始文档。

### 5.6 质量监控

| 指标 | 方法 | 目标（v0） |
|---|---|---|
| 引用命中率 | 程序校验 `evidence_id` 存在且相关 | ≥ 98% |
| 数值一致率 | 与结构化数据比对 | ≥ 99% |
| 分类一致率 | 与人工标注样本（每月抽 50 条）比较 | ≥ 90% |
| 归因一致率 | AI vs 规则引擎 | 分歧率 ≤ 15%，分歧案例全部人工复核 |
| 成本 | 每次运行的 token 与费用记录 | 月度预算内 |

### 6.3 买入 / 卖出点位的方法论

**原则**：区间而非单点；每个区间的前提可查；不确定性显式表达；任何区间都不是收益承诺。

**估值区间（基准价值）**

| 方法 | 公式 | 适用 |
|---|---|---|
| PBR 回归 | 目标 PBR × 最新 BPS；目标 PBR = min(行业中位 PBR, 自身 5 年中位 PBR)，ROE 低于 8% 时再乘以 ROE/8% | 低估反转篮子、金融业 |
| PER 回归 | 目标 PER × 会社予想 EPS；目标 PER = min(行业中位予想 PER, 自身 5 年中位) | 盈利稳定的公司 |
| EV/EBITDA 回归 | 目标倍数 × EBITDA − ネット有利子負債 | 资本密集型、现金充裕公司 |
| 成长调整 | 对成长篮子用「予想 PER ÷ 预期成长率」与行业比较（PEG 式），上限 1.5 | 成长篮子 |
| 情景 | 悲观 = 三法 25 分位 × 盈利下修 10%；基准 = 三法中位；乐观 = 三法 75 分位 × 盈利上修 10% | 全部 |

**买入区间**

- 区间上沿 = 基准价值 × (1 − 安全边际)，安全边际 v0 = 25%（B1）、20%（B2）、30%（B3）；区间下沿 = 悲观价值。
- 分批：40% / 30% / 30%，分别在区间上沿、中位、下沿；错杀篮子要求「企稳」条件满足后才开始第一批。
- 禁止窗口：決算発表预定日前 5 个交易日；重大事件未解释清楚（归因 T6）期间。

**卖出区间与止损**

| 类型 | 规则（v0） |
|---|---|
| 估值减仓 | 价格达到基准价值 → 减仓 50%；达到乐观价值 → 清仓；若基本面证据升级（上方修正）则重算区间 |
| 基本面止损 | 通期営業利益予想下修 > 20%；出现任一硬排除红旗；连续 2 个季度進捗率偏差 < −10 个百分点 |
| 技术止损 | 收盘价 < 入场均价 − 2.5 × ATR(14)（错杀与成长篮子）；低估篮子只用基本面止损与时间止损 |
| 时间止损 | 12 个月内无催化剂进展且相对 TOPIX 落后 > 20 个百分点 → 复核并默认减仓 |
| 流动性退出 | 20 日平均売買代金跌破持仓规模 ÷ (5% × 5 日) → 逐步退出 |

## 7. 验证与迭代方法论

### 7.1 为什么验证优先于优化

本工具的所有参数都是假设。验证的目的不是「证明策略有效」，而是（1）发现数据与规则错误，（2）校准参数到合理区间，（3）识别规则在不同市场环境下的失效模式。过度优化参数会产生漂亮但不可复现的历史结果，因此第 7.5 节规定了防过拟合纪律。

### 7.2 历史回测设计

| 要素 | 要求 | 理由 |
|---|---|---|
| 时点数据 | 财务数据以「披露日」（DisclosedDate）而非会计期末对齐；修订（訂正）只在其披露日后生效 | 避免前视偏差 |
| 幸存者偏差 | 股票池包含回测期内所有曾上市公司（含已退市），退市按最后可交易价处理 | 否则高估低估策略 |
| 企业行动 | 分割、併合、配当用调整因子处理；现金配当计入总收益 | 可比性 |
| 交易约束 | 成交价取次日开盘或 VWAP 近似；涨跌停（ストップ高/安）日不可成交；单票成交量不超过当日売買代金的 5% | 真实性 |
| 成本 | 佣金与滑点合计单边 0.1–0.3%（按流动性分层） | 保守 |
| 频率 | 月度再平衡为主；事件触发（错杀）按事件日 +1 | 与实际运行一致 |
| 基准 | TOPIX（配当込み）、東証規模別指数、简单的价值/成长风格组合 | 多基准避免误判 |
| 样本期 | 取决于数据深度：J-Quants 不同订阅档位的历史深度不同（第 3 章）；至少覆盖 2013 年以来（含 2018、2020、2022、2024 年的调整期） | 跨环境 |

**评估指标**

- 分层检验：按各维度分数分 5 层，观察未来 1/3/6/12 个月收益是否单调。
- 篮子组合：年化收益、波动、夏普、最大回撤、命中率（正收益比例）、换手、成本后收益、相对基准超额与跟踪误差。
- 因子归因：对 Fama–French 日本因子（市场、规模、价值、动量、盈利、投资）做简单回归，报告 α 与各暴露；α 的统计显著性与稳健性一并报告。
- 情景校准：个股卡片的「悲观–乐观」区间在 6/12 个月后对实际价格的覆盖率（目标 70–80%；过高说明区间太宽无信息，过低说明过度自信）。

### 7.3 前瞻跟踪（纸面组合）

- 每次运行生成的组合以纸面方式跟踪，所有入场、出场按卡片规则在次日执行，不允许事后修改规则。
- 预先登记（pre-registration）：每个参数版本在启用前写明「预期表现特征」与「放弃条件」，到期对照。
- 季度评估报告：相对基准表现、分篮子贡献、规则触发统计、AI 质量指标、数据质量指标；评估结论驱动下一参数版本。

### 7.4 跨年度市场环境变化的处理

市场环境（regime）影响的是参数与配置，不是规则本身。设计一个简单、可解释、可回溯的环境标签：

| 指标 | 口径 | 用途 |
|---|---|---|
| 趋势 | TOPIX 相对 200 日均线位置与斜率 | 现金缓冲 |
| 广度 | 全市场收盘价高于 200 日均线的比例 | 现金缓冲、错杀篮子权重 |
| 利率 | 10 年国債利回り水平与 6 个月变化 | 估值锚（V7）、金融业权重 |
| 汇率 | USD/JPY 6 个月变化 | 出口/内需行业倾斜（展示用，不自动调仓） |
| 波动 | TOPIX 20 日实现波动率（自算，推荐）；日経 VI 作人工参考（免费 CSV 仅近 3 年且禁止蓄積） | 止损宽度、分批节奏 |
| 风格 | 价值 vs 成长、小盘 vs 大盘的 6 个月相对表现 | 篮子配置倾斜（±15 个百分点以内） |

规则：环境标签每周更新；参数映射表（环境 → 现金缓冲、篮子倾斜、止损宽度）是附录 C 的一部分，版本化管理；每年年初做一次「年度复盘」，检视上一年各环境下的规则表现，决定是否发布新参数版本。制度性变化（如交易时间延长、披露规则变更、指数改革）作为「制度事件」记录在 `regime_events` 表，回测与评估时按生效日切分样本。

### 7.5 防过拟合纪律

1. 参数只在「允许范围」（第 4.9 节）内调整；越界需书面理由。
2. 每次调参只改一个维度，并同时报告样本内与样本外（最近 2 年留出）结果。
3. 偏好更简单的规则：若复杂规则在样本外不优于简单规则，回退。
4. 参数变更有冷却期：新版本启用后至少跟踪一个季度才允许再次变更同一参数。
5. 所有被放弃的规则与原因保留在「规则墓地」文档中，避免重复试错。

| 陷阱 | 表现 | 对策 |

| 分割与併合 | 价格、EPS、BPS 跳变 | 调整因子，并对企业行动日做一致性测试 |

## 8. 功能边界与非目标

### 8.1 功能边界（In scope）

| 功能 | 边界说明 |

| 验证迭代 | 回测框架、纸面跟踪、季度评估、参数变更管理 |
| AI 分析 | 第 5 章的 A1–A9 任务，带证据约束与质量监控 |

### 8.2 非目标（Out of scope）

- 不接入券商下单接口；不做实时行情与盘中信号。
- 不做宏观预测；环境标签只用于参数映射。
- 不对外提供服务；单用户、本地或单服务器运行。
- 不做衍生品、信用交易策略（信用数据只作为需給指标）。
- v0 不做约束优化器（用规则配置），不做多账户。

### 8.3 运行形态

- 单机（Windows 或 Linux）定时任务即可满足 v0；全部数据与数据库在本地磁盘。数据量级（全量）：日线约 4,000 只 × 可得历史（15–20 年）≈ 1,500–2,500 万行；财务季度记录 ≈ 25–35 万条；适时披露每年 10–15 万条（含 PDF 原件数十 GB/年）；EDINET 法定文件（有報等）每年数万份。结构化部分 Parquet 压缩后数 GB，原始 PDF/XBRL 归档按保留策略可达数百 GB，需为原始档案单独规划磁盘（第 10 章）。
- 无需 GPU；LLM 走 API。

## 10. 数据接入模块与本地数据库设计

### 10.1 设计目标

- **本地**：所有数据（原始文件、标准化表、特征、证据、结果、账本）存放在本地磁盘的数据库与文件湖，无云端依赖；整库可一键备份与还原。
- **全量**：采集对象为全部上市股票（含非目标证券与已退市公司）、各来源可得的全部历史深度、全部数据类别；每个数据集有「应有 / 已有 / 缺口」账本，缺口可回填。
- **不可变原始层**：来源返回的原始内容（JSON/CSV/XLSX/PDF/XBRL）原样落盘并记录哈希与获取时间，之后只追加不修改。
- **可追溯**：每条标准化记录指向其原始文件；每个特征指向其输入记录；每个结论指向其证据。
- **条款合规**：J-Quants 派生数据与免费永久档案（JPX 文件、EDINET、TDnet 原文）分目录存放，便于在解約时按条款删除前者而保留后者（第 19.1 节）。

### 10.2 目录与库结构

```
data/
  raw/                               # 原始层（不可变）
    jquants/{dataset}/{yyyy}/{yyyymmdd}_{hash}.json.gz     # API 响应原样
    jquants_bulk/{dataset}/{yyyymm}/...csv.gz              # CSV 批量下载（Light 以上）
    jpx/{dataset}/{yyyymm}/...xlsx|csv|pdf
    edinet/{yyyy}/{docID}/{meta.json, xbrl.zip, main.pdf, csv.zip}
    tdnet/{yyyy}/{yyyymmdd}/{disclosure_id}/{meta.json, main.pdf, xbrl.zip}
    news/{source}/{yyyymmdd}/...jsonl.gz
    macro/{source}/...
    _quarantine/                     # 校验失败文件
  staging/                           # 标准化层（Parquet，按数据集/日期分区）
  mart/                              # 特征与结果层（Parquet）
  db/
    warehouse.duckdb                 # 分析库（视图指向 Parquet；物化常用表）
    ledger.sqlite                    # 账本、证据索引、复核日志、AI 调用（v0；可迁移到本地 PostgreSQL）
```

### 10.4 连接器通用规范

| 要求 | 实现 |
|---|---|
| 幂等 | 同一（来源, 参数, 日期）重复拉取不产生重复记录；以原始文件哈希判重 |
| 增量与回填 | 每个连接器支持 `--since` 增量与 `--backfill --from --to` 回填；回填按来源速率分批执行并可断点续传 |
| 速率与礼貌 | 遵守来源的速率限制（J-Quants：按套餐 req/分，财务端点 60 req/分，429 时按 1 分钟滑动窗退避）与 robots 规则；无 API 的网页来源只在授权允许范围内低频访问 |
| 失败处理 | 指数退避重试；失败写入 `completeness_ledger` 的缺口原因 |
| 校验 | 行数、主键唯一、必填字段、数值范围；失败文件隔离到 `raw/_quarantine/` |
| 时间 | 一律记录 JST 与 UTC；披露时间保留到分钟 |
| 版本 | 来源 API 版本（如 J-Quants `v2`）、解析器版本写入每条记录 |
| 分页 | J-Quants 响应 `{"data": [...], "pagination_key": ...}`，循环直到无 `pagination_key` |

## 11. 特征与指标计算模块

### 11.1 时点（PIT）对齐规则

- 财务指标的「生效日」：披露时刻（DiscTime）早于 15:30 → 披露当日（当日收盘价已反映）；15:30 及以后或时刻缺失 → 次一交易日。约 36% 的決算短信在盘中披露（第 3.7 节）。
- 每个财务记录保留 `period_end`、`disclosed_at`、`effective_date`、`revision_no`；修订记录只覆盖其生效日之后的计算。
- 行情、信用、空売り数据按发布日生效；周度数据在发布日后生效。
- 特征表的主键为 `(code, as_of_date)`，所有指标都记录其输入记录的 ID，保证可回溯。

### 11.2 企业行动与口径

- 使用调整因子处理分割/併合；EPS、BPS、DPS 按同一因子调整。
- 連結优先，无連結时用単体并标记 `consolidation = 'parent'`。
- 会计准则标签 `gaap ∈ {JGAAP, IFRS, USGAAP}`；営業利益在 IFRS 下使用「営業利益」对应项，若公司不披露则用「税引前利益 + 金融費用」近似并标记。
- 决算期变更（決算期変更）：期间月数不为 12 时，增长率按年化折算并标记 `fy_months`。
- 单位统一：金额円（短信中的百万円 × 10^6），股数为股，比率为小数。

### 11.3 同业百分位与历史百分位

- 同业组：33 業種（全市场合并）；样本不足回退 17 業種 → 全市场。
- 百分位在每个 `as_of_date` 上重新计算，只用当日可知数据。
- 历史百分位：窗口 5 年（1,250 个交易日），不足 2 年则标记低置信。

### 11.4 质检规则（每日）

| 规则 | 动作 |
|---|---|
| 覆盖率：行情覆盖 ≥ 99% 股票池 | 否则告警，暂停发布清单 |
| 跨源一致：PBR/PER 与第二来源差异 ≤ 5%（抽样 100 只） | 超限标记「口径待查」 |
| 异常值：单日价格变动 > 30% 且无企业行动/事件 | 人工核查 |
| 单位错误：净资产/总资产 > 1 或 EPS 与净利润/股数差异 > 2% | 标记并排除当日评分 |
| 新鲜度：最新短信距今 > 135 天 | 标记 `stale_financials` |

## 12. 筛选引擎

### 12.1 规则配置化

- 所有硬过滤、软过滤、维度指标、权重、阈值来自 `params.vX.yaml`（附录 C），引擎不内置数字。
- 每条规则有 `rule_id`、`description`、`rationale`、`evidence_level`、`params`，便于输出可解释结果。
- 引擎输出每只股票的 `rule_hits`（命中的规则 ID 列表）与 `exclusion_codes`。

### 12.2 运行模式

| 模式 | 输入 | 输出 |
|---|---|---|
| `daily-incremental` | 当日特征 | 新进入/移出候选的差异、错杀触发 |
| `weekly-full` | 当周特征 | 完整清单、篮子 Top N |
| `backtest` | 历史特征（PIT） | 按月滚动的历史清单，供验证框架 |
| `replay` | 指定 `run_id` | 用当时快照与参数重现结果（校验和须一致） |

### 12.3 性能预算

- 全市场单日评分 < 5 分钟（DuckDB/Polars 向量化）；回测 15 年月度 < 1 小时。

## 13. AI 分析服务

### 13.1 组件

| 组件 | 职责 |
|---|---|
| 证据包组装器 | 按任务类型拼装结构化指标、事件列表、文档片段；为每个片段分配 `evidence_id` |
| 提示模板库 | 每个任务一个模板，版本化（`prompt_version`）；稳定部分放前缀以命中缓存 |
| 调用器 | 同步（候选池）与批处理（全市场）两种路径；重试、速率限制、超时 |
| 校验器 | JSON Schema 校验（附录 E）、引用存在性与相关性、数值一致性、多次采样一致性 |
| 缓存 | 键 = (文档哈希, 任务, prompt_version, model_version)；命中则不调用 |
| 账本 | 每次调用的 token、费用、耗时、模型、结果状态 |

### 13.2 实现要点

- 文档输入优先用「抽取文本 + 页码」；PDF 直传只用于版式复杂的短信附表。
- 结构化输出使用 API 的 JSON Schema 约束；引用使用 API 的 citations 能力并映射到 `evidence_id`。
- 对 Opus 级模型的调用默认开启自适应思考与较高 effort；批量分类任务用较低 effort。
- 所有提示语与输出以 UTF-8 保存，输出中保留日文原文片段。
- 拒答或异常（如安全分类器拒绝）时记录并回退到规则结果，不阻塞管线。

## 14. 组合构建与风险模块

### 14.1 流程

1. 读取各篮子 Top N 与特殊情形池，过滤软排除与「待決算」。
2. 按篮子配置比例分配名额；篮子内按复合分降序，同时满足行业/市场区分/流动性约束（贪心填充，v0）。
3. 计算目标权重：分层等权（Top 10 权重 1.2×，其余 1.0×），再按 60 日波动率倒数调整，归一化到 (1 − 现金缓冲)。
4. 与当前持仓比较，生成变动建议（新增/移除/调整），每笔附触发条件与理由码。
5. 计算暴露与风险指标，生成组合报告。

### 14.2 买卖区间与触发条件计算

- 按第 6.3 节公式计算三情景价值、买入区间、减仓价位、止损线；全部写入个股卡片与 `signals` 表。
- 触发条件以可机检规则表达（例如 `close < entry_avg - 2.5*atr14`），每日检查并生成提醒；执行与否由人工决定。

### 14.3 风险指标实现

- 事前波动率与 β：60/250 日日收益协方差；情景压力用线性近似（β × 指数冲击，行业/汇率敏感度来自历史回归，仅展示）。
- 流动性退出天数：持仓 ÷ (20 日平均売買代金 × 5%)。
- 因子暴露：对 Fama–French 日本因子做滚动回归（展示用）。

### 15.2 新股纳入流程

1. 上市列表刷新发现新代码 → 建立主数据 → 标记 `listing_date`。
2. 进入「新股观察池」：只计算行情与事件特征；估值指标用招股说明书（有価証券届出書）中的财务数据作为初始值并标记 `ipo_prospectus_based`。

- 上場廃止決定 → 立即硬排除；保留历史数据供回测（幸存者偏差）。

- 市场区分变更（如 Growth → Prime）：记录生效日；行业分类变更同理。
- 合并（吸收合併）：被吸收方按退市处理，吸收方保留。

### 15.4 跨年度市场环境变化

- `regime_events` 表记录制度性事件（交易时间变更、披露规则变更、指数改革、市场区分改革等）及生效日。
- 环境标签每周计算并写入 `regime_weekly`；参数映射表版本化。
- 年度复盘输出：各环境下规则表现、失效规则、建议的参数版本。
